Bug fixes found during verification:
- app.py: POST /api/reports/<id>/resubmit was gated behind
  @roles_required('publisher', 'admin'), but roles aren't permanent -
  an admin can demote a publisher back to basic via manage_users.py
  without touching their existing reports. A publisher demoted while
  a report sat in changes_requested would be permanently unable to
  resubmit it. Switched to @login_required, relying on the route's
  own identity check (report.uploaded_by == user.id). Verified: a
  demoted uploader can now resubmit (200); a stranger still gets 404.
- notification.py: fixed a stale docstring reference to '2nd distinct
  approval', left over from before REQUIRED_APPROVALS was corrected
  from 2 to 3.

Security audit and fix:
- Audited CORS/session cookie config, CSRF exposure, SQL injection
  surface, password reset token generation, rate limiting coverage,
  login/signup/forgot-password email-enumeration resistance, session
  fixation on login, auth decorator coverage across every mutating
  and sensitive GET route, and Stripe webhook signature verification -
  all already solid.
- app.py: report cover images were validated by extension only, with
  the browser-supplied (attacker-controlled) Content-Type stored and
  served back verbatim. The local storage backend's own
  X-Content-Type-Options: nosniff covered this, but the S3 backend -
  required in production - serves files via a redirect straight to a
  presigned URL, entirely outside this app's response headers, so
  nosniff never applied there. Now verifies every uploaded cover
  image is genuinely decodable via Pillow (already a dependency, used
  the same way for fellow photos) before saving, rejecting non-image
  content regardless of its extension or declared Content-Type.
  Verified: a genuine PNG still uploads; a script tag renamed to .png
  is rejected with a 400.
