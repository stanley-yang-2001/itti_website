Wire up admin/publisher GTBI+ETTI workbook upload end-to-end

Connects the existing but disconnected pieces (globe_data.py,
PublishGlobeData.jsx) into a working upload flow, and fixes the
admin-exclusion bug that would've blocked admins from using it.

Backend:
- Add POST /api/globe-data/upload (roles_required: publisher, admin).
  Validates the workbook using the same extraction code the CLI
  scripts use, archives the raw upload, rotates
  data_scripts/{kind}_source/ (old file -> old/, new file installed),
  refreshes the cached {kind}_country_data.json, and merges the result
  into server/data/country_data.json - touching only the uploaded
  kind's section per country.
- globe_data.py: add rotate_source_file() and sync_cached_extraction()
  alongside the existing validate_workbook()/archive_workbook()/
  apply_workbook_to_country_data().

Frontend:
- Route PublishGlobeData.jsx at /publish/globe-data (unwrapped in
  ProtectedRoute, per its own self-guarding design) and link it from
  the Publish hub.
- Fix AuthContext's isPublisher and ProtectedRoute's requireRole check,
  both of which only matched role === 'publisher' and silently
  excluded admins, despite the backend already treating admin as a
  superset of publisher everywhere else.

Verified via Flask test client: 401/403 for anonymous/basic users,
200 for publisher and admin, 400 with no filesystem side effects for
corrupted or wrong-shape workbooks, correct old/-folder rotation and
country_data.json merge behavior. Frontend changes verified with a
clean `vite build`.
