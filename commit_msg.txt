Add user Profile page with Favorites and Publications

server/models/favorite_report.py (new)
- FavoriteReport model + CRUD (add/remove/list), mirroring the existing
  saved_chart.py pattern: a thin join row rather than a denormalized
  copy, so a favorite always reflects the report's current state.

server/migrations/versions/a1f9c3d7e5b2_add_favorite_reports.py (new)
- Adds the favorite_reports table. Applies cleanly on top of the full
  existing migration chain.

server/app.py
- GET    /api/reports/mine          - the logged-in user's own reports,
                                       any review_status
- GET    /api/reports/favorites      - the logged-in user's favorited
                                       reports (full objects)
- GET    /api/reports/favorites/ids  - just the id set, for marking
                                       stars cheaply on a list of cards
- POST   /api/reports/<id>/favorite  - favorite a report (idempotent)
- DELETE /api/reports/<id>/favorite  - unfavorite a report

client/src/pages/Profile.jsx (new), client/src/styles/Profile.css (new)
- Header (avatar/initials, name, email, role badge, member since).
- Favorites: Observatory charts (using the save-to-profile flow that
  already existed in ChartsSection.jsx) and favorited Reports.
- Publications: publisher/admin users get a list of their own reports
  with status badges and a "New Report" button reusing the existing
  ReportUploadForm workflow unchanged; other users see a message
  directing them to contact@itti.org to request publisher access.
- Quick Links to Settings, Certifications, Donate, and Contact.

client/src/components/ReportCard.jsx
- Optional favorite-star toggle (isFavorited/onToggleFavorite props),
  omitted entirely when not supplied rather than rendering inert.

client/src/pages/Reports.jsx
- Loads the current user's favorite id set and wires the star on each
  card, with an optimistic toggle that reverts on failure.

client/src/components/NavBar.jsx
- The logged-in user's name/role block is now a link to /profile.

client/src/App.jsx
- New protected routes: /profile and /settings (Settings.jsx existed
  in the repo already but had no route at all until now).

client/src/api.js
- fetchMyReports, fetchFavoriteReports, fetchFavoriteReportIds,
  favoriteReport, unfavoriteReport.

Verified end-to-end with a live backend + real browser: signup,
publisher promotion, report creation, favoriting/unfavoriting (both
reports and charts), deleting a saved chart, and the non-publisher
