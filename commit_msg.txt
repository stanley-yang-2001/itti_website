Fix fellow/report images crashing with 500 in production

Root cause: uploaded file paths (fellow photos, report files/images,
documents) were stored as absolute, machine-specific paths baked in
by whoever ran the upload locally - unusable on the deployed server,
which crashed serving them with a raw FileNotFoundError instead of a
handled 404.

- storage.py: LocalStorage now stores/resolves paths relative to its
  own base_dir instead of absolute ones, and get_file_response()
  catches a missing file and returns a clean 404 instead of crashing
- Add migrate_absolute_storage_paths.py: one-off, idempotent script
  to repair existing bad rows (fellows/reports/documents) wherever
  the underlying file can still be found
- app.yaml + docs/DEPLOYMENT.md: document and configure
  STORAGE_BACKEND=s3 (DigitalOcean Spaces) for production, since
  local disk doesn't survive App Platform's per-deploy container
  rebuilds
