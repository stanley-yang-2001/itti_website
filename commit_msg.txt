Fix session-caching account leak; fix app-breaking stale filename reference

Someone with no credentials could end up "logged into" another
person's account from a different machine. Root cause: nothing in
this API ever set Cache-Control, so a shared cache sitting in front of
it (CDN, corporate/ISP proxy, or even the visitor's own browser cache)
was free to store and replay a cached /api/auth/me response - which
from the frontend's point of view is indistinguishable from actually
being logged in, even though the victim's browser never sent the
original session cookie at all.

- server/app.py
    - set_security_headers() now sets Cache-Control: no-store and
      Vary: Cookie on every response, not just auth ones - this app
      mixes public and personalized endpoints under one origin, and a
      blanket no-store is safer than trying to allow-list which
      routes are "safe" to cache.
    - session.pop("user_id", None) -> session.clear() in auth_me's
      stale-session cleanup, auth_logout, and delete_account - purely
      defense-in-depth (pop already correctly invalidated the cookie
      in testing), guards against any future session key being missed
      on logout.
    - Added an explicit PERMANENT_SESSION_LIFETIME of 7 days - was
      silently defaulting to Flask's 31-day default, which is a long
      window for any leaked/cached cookie to stay valid.
- client/src/context/AuthContext.jsx
    - The /api/auth/me fetch on mount now passes cache: 'no-store' -
      explicit defense-in-depth on top of the server header, directly
      on the request that turns a cached response into "someone else
      is in my account."

while verifying the above: the prior commit renamed
data_scripts/country_profiles.extract.py -> country_profiles_extract.py
but didn't update the two hardcoded path references to it. Since
app.py imports country_profiles_upload unconditionally at startup,
this currently crashes the entire app on boot (FileNotFoundError).
- server/country_profiles_upload.py
- server/data_scripts/merge_remainder_profiles.py
    Both updated to the renamed filename; a stale comment describing
    the old dotted filename was also cleaned up.
