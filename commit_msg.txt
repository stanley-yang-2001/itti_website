Reconcile modal/admin work with upstream, fix broken migration chain

Merged my prior work (Stripe enrollment modal, privacy policy modal +
checkbox, admin user management) onto a substantially reworked upstream
baseline (refined color palette, --globe-bg separating the globe
visualization from page chrome, new shared .btn utility classes, a new
country-profiles narrative content feature, an AdminDonations page).
Adopted upstream's version of each shared file as the new baseline,
then re-layered my specific additions on top rather than overwriting:

- App.css: restored .navbar--scrolled (see below) and the .app-modal-*
  generic modal system, both missing from the upstream rework.
- Certifications.css: restored .cert-refund-note.
- Settings.css: restored .manage-users-* (admin panel styles).
- SignUp.css: restored .signup-checkbox-field/.signup-field-hint/
  .signup-privacy-link, updated to the new var()-based color
  conventions upstream introduced for this file.
- Login.css: restored .login-field-hint (used by ResetPassword.jsx,
  which upstream hadn't touched but whose CSS lives in this file).
- app.py: kept the new GET /api/country-profiles routes, re-added the
  admin user-management routes and the get_all_users/VALID_ROLES
  import they need.

Bug found and fixed: NavBar.jsx's scroll-shrink behavior was silently
broken on the deployed site - it still applies the "navbar--scrolled"
class on scroll, but the CSS rules for that class had been dropped
during the upstream palette rework. Restored them.

Migration chain fork found and fixed: a1f9c3d7e5b2 (add_favorite_reports)
and c8e4f1a02b3d (index donations.stripe_payment_intent_id) were both
independently chained onto the same parent (9a7c1e2b6f4d, add_donations),
producing two divergent heads - `alembic upgrade head` would fail
outright with "Multiple head revisions are present" for anyone running
it. Added f3a29d6c81e0, a standard Alembic merge migration (no schema
changes, just reconciles the graph into one linear head).

Also removed: 6ff385893016_add_category_to_reports.py, an empty file
with no `revision` variable at all. Confirmed nothing in the codebase
actually implements a reports "category" column, and a migration
Alembic can't parse could never have been applied to any database, so
it was pure dead weight - and was actively blocking Alembic from
loading the migration directory at all, a bigger problem than
previously flagged.

Verified: `vite build` clean against the fully merged frontend; fresh
`alembic upgrade head` against a clean SQLite database applies the
entire chain without error and produces all 11 expected tables
(including enrollments); backend route tests confirm both the restored
admin routes and the new country-profiles routes work together.

Not done here: AdminDonations.jsx exists but isn't wired into App.jsx's
routing - same "built but not connected" pattern seen elsewhere in this
repo (PublisherDashboard.jsx, ReportUploadForm.jsx were the same before
being routed in earlier work). Flagged, not fixed, pending direction.
