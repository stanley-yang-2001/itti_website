====================
CHANGE DETAILS
====================

Server load reduction:

- Flask-Compress: gzips every JSON response above 500 bytes for any
  client that accepts it - no frontend change needed. Wired in before
  set_security_headers is registered so compression runs as the true
  last step (Flask runs after_request hooks in reverse registration
  order), after headers/ETag are computed on the real response.
- Real HTTP caching (public, ETag, conditional-GET via a new
  cacheable_json_response() helper) on the four hottest, genuinely
  public, non-personalized GET endpoints: /api/world-data,
  /api/countries(/<code>), /api/country-profiles(/<code>). Required
  changing Cache-Control: no-store from an unconditional overwrite to
  a safe default via setdefault() - every other route, including
  auth/notification endpoints, is unaffected and still gets no-store.
- Fixed a real N+1 query bug: GET /api/reports/<id>/reviews was
  opening a new DB session per review row to look up the reviewer's
  name. reviews_to_public_dicts() batches that into one query.
- React.lazy() code-splitting for 21 of 22 pages (Home stays eager).
  Previously zero code-splitting existed anywhere - visiting the
  homepage meant downloading the entire app regardless of which page
  someone came for.
- Image optimization: logo/map pngquant-compressed, certification
  images resized to match their actual ~900px display width and
  recompressed. All verified visually - no visible quality loss.
- Reconciled twice against upstream while in flight (a homepage-icons/
  Facebook-link commit, then a large peer-review-notifications/
  report-resubmission feature touching the same files) - reapplied
  each piece individually rather than force-merging, confirmed nothing
  from either side was lost.

Report panel image + upload limits:

- Fixed image cropping: .report-card-image used object-fit: cover
  with a fixed height, cropping any image whose aspect ratio didn't
  match. Switched to object-fit: contain - every image now displays
  in full, letterboxed rather than cut off. Verified visually with a
  real portrait test image rendered through the actual CSS.
- Added upload guidance (1200x630px, landscape) to both
  ReportUploadForm.jsx and ResubmitReportForm.jsx - found and fixed
  both, since the newer resubmit flow has its own separate cover-image
  field with the same gap.
- Description limited to 200 characters (was 2000) - server
  (validation.py) and client (formValidation.js) both updated and
  verified matching. Live "142/200" character counter next to the
  Description label in both upload forms, turning red at the limit.
- New 2.5MB combined limit for report file + cover image together,
  enforced server-side in a restructured _save_report_upload() that
  checks the combined total BEFORE writing anything to storage (previously
  the file was saved, then the image checked, then deleted on
  failure). A new report-specific MAX_REPORT_COMBINED_BYTES constant
  was added rather than changing the existing MAX_UPLOAD_BYTES, which
  is shared with an unrelated upload endpoint. Live "X.XX MB of a
  2.5 MB combined limit" indicator on both forms, updating as either
  file is selected, red when over, plus client-side validation so
  users find out before submitting.
