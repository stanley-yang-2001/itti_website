feat: add peer-review workflow to Reports

Reports no longer publish directly. Every upload now starts as
pending_review and must clear peer review before it appears on the
public Reports page:

  pending_review --(3 distinct approvals, not from the uploader)--> published
  pending_review --(any single reject, with a required comment)--> changes_requested
  changes_requested --(uploader resubmits)--> pending_review, version += 1

Rejection doesn't delete the report - it sends it back to the
uploader with the reviewer's comment. The uploader resubmits a new
file/description (plus an optional note addressing the feedback),
which bumps the report's version and resets it to pending_review.
Approvals are scoped to that version, so a resubmission genuinely
starts review over: prior approvals from before the rejection don't
carry forward and count toward the new 3.

New routes (all in server/app.py):
  GET  /api/reports/pending              - publisher/admin only
  GET  /api/reports/changes-requested     - publisher/admin only
  POST /api/reports/<id>/resubmit         - uploader only
  POST /api/reports/<id>/review           - publisher/admin only
  GET  /api/reports/<id>/reviews          - publisher/admin only

GET /api/reports (public) now returns only published reports.
GET /api/reports/<id>, .../file, and .../image now restrict
non-published reports to their uploader or a publisher/admin, rather
than any visitor - a pending or rejected submission is not public
just because you have its URL.

New models:
  - report_review.py: ReportReview (one row per report+reviewer+
    version) and record_review(), the single entry point enforcing
    every rule (no self-review, comment required on reject, 3rd
    distinct approval auto-publishes)
  - report.py: adds review_status, version, resubmission_note,
    updated_at; resubmit_report() applies a resubmission

Fixes a real bug caught while testing: Report.to_public_dict() used
to read the uploader relationship directly, which raises
DetachedInstanceError once the session that loaded the report has
closed (e.g. immediately after create_report() returns). Author name
is now resolved through its own short-lived query
(get_author_name()), so to_public_dict() is safe to call regardless
of session state - the same pattern is used for ReportReview's
reviewer_name.

validation.py: adds check_resubmission_note and check_review_comment
(length-capped; "required for reject" is enforced in
report_review.py itself, since that depends on the decision, not
just the value).

models/__init__.py: registers report and report_review so their
relationships resolve correctly (matches this file's existing
pattern for every other model).

migrations/3dd530f4f775: adds resubmission_note/review_status/
version/updated_at to reports, plus the new report_reviews table.
Chained after 1b00e3b253a1 (add_saved_charts) rather than directly
after c37ebaee3d80 (add_reports_table): both migrations initially
branched from c37ebaee3d80, but 1b00e3b253a1 was already pushed
first, so this one re-parents onto it to keep migration history
linear instead of requiring an Alembic merge migration. Existing
report rows get review_status='published' via server_default, so
reports already live before this migration stay visible rather than
retroactively requiring review.

Verified end-to-end against a real SQLite database: upload stays
non-public through 0/1/2 approvals and auto-publishes on the 3rd;
self-review is blocked; reject without a comment is rejected;
rejected reports move to a separate changes-requested list and can't
be reviewed further until resubmitted; resubmission correctly resets
the approval count so a prior version's approvals don't count toward
the new one.

Not yet built: the frontend Peer Review page and the updated Reports
page UI (author/date display, approve/reject controls). This commit
is backend-only.
